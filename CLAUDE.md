# iso-knight — инструкции для Claude

Прототип изометрической игры (three.js 0.180, ES-модули, без сборки). Две страницы: `index.html` — рыцарь, `soldier.html` — солдат со стрельбой в духе Project Zomboid. Отвечать пользователю по-русски.

## Как проверять изменения

1. `npm run check` — синтаксис всех модулей.
2. `npm start &` — сервер на :8777 (three.js из `vendor/`, сеть не нужна).
3. Скриншоты: `npm i` (ставит playwright), при необходимости `npx playwright install chromium`, затем
   `PLAN='[...]' node tools/shots.cjs shots`. На Linux используется встроенный Chromium; `PW_CHANNEL=chrome` — системный Chrome.
   Если локальный playwright новее браузеров в `/opt/pw-browsers` (облачная среда), запускать с
   `PLAYWRIGHT_MODULE=/opt/node-tools/node_modules/playwright`.
   Кадры детерминированы: цикл rAF отключён, игра идёт только через `step()`, `Math.random` сидирован (`LIVE=1` — живой цикл).
   Поэтому рефакторинг рыцаря проверяется попиксельным сравнением кадров до и после.
   План — массив шагов: `{"reset":[x,z,yawDeg]}` ставит героя, `{"view":[camYawDeg, zoomMeters]}` — камера,
   `{"input":{"mx":1,"mz":0,"run":true,"block":false}}` — удерживаемый ввод (экранные оси), `{"attack":1}` — удар,
   `{"step":0.3}` — промотать симуляцию (60 Гц), `{"name":"x","clip":{...}}` — сохранить `shots/x.png`.
   Пример: `PLAN='[{"reset":[0.3,1.4,90],"view":[0,3.2]},{"attack":1,"step":0.19,"name":"windup"}]'`.
   `python -I tools/sheet.py out.png shots/*.png` собирает контактный лист (нужен Pillow).
   Солдат: `PAGE=soldier.html`. Любой другой ключ шага вызывает одноимённый хук `window.__game` с аргументами:
   `{"aim":[x,y,z]}` — держать прицел на мировой точке (`{"aim":false}` — опустить), `{"fire":1}` — нажать спуск,
   `{"trigger":true|false}` — держать спуск, `{"mode":0|1|2}` — одиночный/очередь/автомат, `{"reload":1}`, `{"attack":1}` — толчок,
   `{"crouch":true}`, `{"option":["pan",false]}` — выключить смещение камеры к прицелу (для крупных планов).
   `EVAL='__game.probe()'` печатает в конце линию огня, что она пробивает и шанс попадания по каждой мишени.
4. Смотреть кадры глазами перед тем, как считать анимацию готовой. Ошибки страницы печатаются в конце вывода shots.

## Соглашения

- 1 единица = 1 м, +Y вверх, персонаж смотрит в +Z, правая рука (меч) на −X, левая (щит) на +X.
- Камера: ортографическая, возвышение 30°, позиция привязана к пиксельной сетке рендера.
- Анимация процедурная (`src/knight-rig.js`, `src/soldier-rig.js`), клипов нет. Новые движения — ключи в `ATTACKS`/`MELEE`/`RELOAD` или слои в `update()`.
  Общее (IK, пружины, кривые, походка) — в `src/rig-core.js`, конструктор моделей — `src/rigid-kit.js`; при правках там проверять, что кадры рыцаря не изменились.
- Солдат: винтовка — кость в пространстве корня, её поза задаётся в пространстве груди (`POSE` в `soldier-rig.js`), руки решаются IK на хваты `GRIP_R`/`GRIP_L`.
  Точки оружия (дуло, выброс гильз, антабки, шахта магазина) — `GUN` в `soldier-model.js` (начало координат — спуск, +Z — к дулу, +X — левый бок).
  Пули идут через `world.trace()`; мишень — объект с `test(o, d)` (аналитическая проверка) и `hit()`; пластины мишеней не регистрировать в `solids`, иначе рейкаст перехватит попадание.
- Палитра мира берётся из общих текстур (`makeMaterial`/`makeTexture` в `src/textures.js`), новые объекты делать так же: 64×64, NearestFilter, flatShading.
- `reference/` — чужой эталон, не редактировать.

# Изометрический рыцарь «Последний караул»

Отдельный графический прототип: низкополигональный персонаж, ортографическая камера, приглушённая палитра и пиксельное увеличение. Геометрия и текстуры созданы для этого прототипа; ассеты Project Zomboid не использованы. Код и данные существующего автобоя не менялись.

## Посмотреть

Из этой папки:

```powershell
npm install
npm start
```

Открыть <http://127.0.0.1:8766>. После установки Three.js интернет для просмотра не нужен. Сервер слушает только локальный интерфейс.

Перетаскивание поворачивает камеру, колесо меняет масштаб. Кнопки направлений переключают ракурс с шагом 45°. `1`, `2`, `3` включают покой, ходьбу и удар; пробел ставит анимацию на паузу. Доступны автоповорот, сетка полигонов, переключение площадки и пиксельного масштаба. Кнопки ¼× / ½× / 1× меняют скорость, ползунок кадров останавливает анимацию в выбранной фазе. Переключение действий смешивает позы за 0,18 с.

## Готовые файлы

| Файл | Содержимое |
| --- | --- |
| `knight.glb` | Модель со встроенными текстурами, скелетом и клипами `Idle`, `Walk`, `Attack` |
| `turnaround.png` | Обзор всех восьми направлений |
| `preview.png` | Снимок просмотрщика |
| `rear-view.png` | Проверочный ракурс со спины |
| `knight-idle.png` | 8 направлений, по одному кадру, прозрачный фон |
| `knight-walk.png` | 8 направлений × 16 кадров ходьбы, прозрачный фон |
| `knight-attack.png` | 8 направлений × 24 кадра удара, прозрачный фон |
| `walk-poses.png` | Ключевые фазы шага сбоку |
| `attack-poses.png` | Ключевые фазы диагонального удара |
| `sprites.json` | Размеры кадров, порядок направлений, длительности и общая точка опоры |

GLB можно импортировать в Godot или Blender как обычную glTF-модель. В Unity потребуется импортёр glTF. В этой среде проверена повторная загрузка через `GLTFLoader`; импорт непосредственно в Godot и Blender не проверялся, этих редакторов здесь нет.

## Устройство

- 4 316 треугольников, 19 костей, 9 материалов, текстуры по 64 × 64 пикселя.
- Одна единица — один метр; вверх `+Y`, лицо направлено вдоль `+Z`. Начало координат расположено на уровне земли между стопами. Высота около 1,8 м в стойке.
- В исходнике один `SkinnedMesh`; при загрузке GLB Three.js разбивает его на 9 частей по материалам. У всех частей один скелет.
- Доспех имеет жёсткие веса: каждая вершина относится к одной кости. Это сохраняет форму металлических деталей. Кости `Shield` и `Sword` позволяют менять положение оружия; геометрия оружия включена в общий меш.
- Три анимации на месте, записанные с 60 отсчётами в секунду: `Idle` — 2,4 с, `Walk` — 1,16 с, `Attack` — 1,8 с. Перемещение по миру, коллизии, попадания, root motion и игровая логика не входят в этот графический прототип.
- При рендере спрайтов камера поднята на 35,26°; размеры кадра и точка опоры одинаковы для всех действий. Обозначения направлений относятся к положению камеры вокруг персонажа.

`model.js` создаёт геометрию и детерминированные текстуры, `animation.js` — позы и ключи анимаций. `viewer.js` отвечает за сцену, управление и экспорт. `server.mjs` раздаёт локальные файлы. Three.js 0.180.0 используется по лицензии MIT, её текст находится в установленном `node_modules/three/LICENSE`.

## Движение

Ходьба рассчитана через двухзвенную обратную кинематику ног: 60% цикла занимает опора, 40% — перенос. Перекат с пятки на носок учитывает нижнюю плоскость подошвы; колено всегда направлено вперёд. Максимальный подъём переносимой стопы — 11,2 см. Поворот таза, встречный поворот плеч и небольшое вертикальное смещение сопровождают шаг.

Это цикл на месте для подключения к игровому перемещению. При движении персонажа вперёд со скоростью 0,63218 м/с плоская часть опорной фазы не скользит относительно мира; в стационарном просмотрщике она движется назад относительно корпуса, как на дорожке.

Удар начинается из низкой стойки: подготовка над плечом, поворот таза и грудной клетки, короткий подшаг, диагональный проход справа сверху влево вниз, доведение и возврат. Локоть и кисть рассчитываются от траектории хвата. Меч ориентирован вдоль оси хвата, с поворотом кисти, ближайшим к направлению предплечья. Щит отводится, освобождая траекторию.

Задержка движения кисти и клинка, просадка после шага и затухающая реакция щита создают ощущение инерции. Это воспроизводимые аналитические колебания, записанные в анимацию; физического движка и реакции на столкновения здесь нет.

## Проверка и воспроизведение экспорта

`verify.cjs` использует Playwright и установленный Chrome: открывает сцену, проверяет элементы управления и узкую компоновку, сохраняет ракурсы, экспортирует GLB и повторно загружает все три клипа. `--export` также пересоздаёт спрайты и обзор ракурсов. Путь к уже установленному Playwright можно передать через переменную `PLAYWRIGHT_MODULE`; иначе используется пакет `playwright` из окружения Node.js.

```powershell
node verify.cjs --export
node check-motion.cjs
```

Исправлена инверсия порядка вершин боковых поверхностей и крышек кольцевых деталей. После исправления визуально проверены все восемь направлений. Материалы остаются односторонними, так что ошибка не скрыта двусторонней отрисовкой.

`check-motion.cjs` проверяет 241 момент каждого клипа: контакт подошв, досягаемость кистей и стоп, направление коленей, отсутствие скачка на шве цикла и скольжение плоской опорной стопы с учётом скорости перемещения. Результаты — `motion-check.json`. `export-check.json` содержит сравнение координат костей исходной и повторно загруженной GLB-анимации в шести промежуточных моментах каждого клипа, допуск 5 мм.

Общие тесты репозитория `scripts/test.sh` были вызваны, но не стартовали: на этой машине отсутствует требуемый .NET SDK 10.0.401. Ядро боя и хеши детерминизма не менялись и в этом запуске не проверены.

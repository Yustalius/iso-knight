# Симуляция без графики и боты на правилах

Первая итерация плана из [`bots.md`](bots.md). В ней есть быстрая детерминированная симуляция боя отрядов и боты на правилах с разными стратегиями. Составы от 1×1 до 10×10, включая неравные. Есть инструменты, чтобы гонять тысячи матчей и смотреть кадры.

Решения итерации:

- Игра для ПК на Godot 4 (C#), веба нет.
- Правила — отдельная .NET-библиотека без зависимостей. Её одинаково используют будущая игра, арена ботов и обучение.
- Godot-проекта и моста в Python пока нет, но API под них уже заложен.

## Запуск

Нужен .NET 8 SDK.

```sh
cd sim
dotnet test Squad.Tests                       # 41 тест: математика, видимость, баллистика, оружие, утечки, детерминизм, боты
dotnet run --project Squad.Tools -c Release -- <команда>
```

| Команда | Что делает |
|---|---|
| `mapgen --players 7v5 --seed 3 [--asym] --out out/map.png [--json map.json]` | превью сгенерированной карты |
| `render --scenario scenarios/asym-7v5.json --seed 1 --from 0 --to 60 --every 5 --cols 4 --focus 0` | кадры матча сверху и контактный лист PNG; `--focus` — чьи знания рисовать |
| `arena --scenario F --matches 400 --swap [--sizes 4v6] [--list]` | матчи на всех ядрах. Выдаёт победы с доверительным интервалом, причины конца, длину и статистику по стратегиям. При случайных составах — разбивку по разнице в людях |
| `crosstab --brains rusher,holder,... --size 3 --matches 60` | матрица «стратегия против стратегии» |
| `bench` | мкс на тик (только симуляция и симуляция с ботами), байт аллокаций на тик |
| `replay record --scenario F --seed 4 --out f.rpl` / `replay verify f.rpl` | записать и проверить реплей |

## API

```csharp
var m = Match.Create(config);          // MatchConfig: seed, карта, правила, баланс, две команды AgentSetup
m.Step(actions);                       // один тик 1/30 с; actions[i] — действие солдата i
AgentView v = m.View(i);               // всё, что знает солдат i; перестраивается 10 раз в секунду
m.ViewUpdated(i);                      // вид перестроен на этом шаге — момент решения бота
m.Events;                              // события тика: Shot (трассер), Hit, Kill, Reload*, DryFire, Sound, NearMiss, RoundEnd
m.Truth(i);                            // точное состояние для рендера и инструментов; ботам нельзя
m.Result; m.Tick; m.Hash();
```

### `AgentAction` — одинаковый для человека, бота на правилах и сети

| Поле | Значение |
|---|---|
| `Move` + `Target` | `Dir` — направление (длина ≤ 1); `To` — точка, путь строит симуляция; `None` |
| `Mode` | `Walk`, `Run`, `Sneak` |
| `Stance` | `Stand`, `Crouch` |
| `AvoidThreats` | путь в обход клеток, которые видят известные угрозы (для обхода) |
| `Aim` + `AimAt` / `AimPoint`, `AimHeight` | наведение на контакт (по своей, неточной оценке) или на точку; `None` — винтовка опущена |
| `Trigger` | `Single`, `Burst` срабатывают по нажатию (переход из `None`); `Auto` стреляет, пока держишь |
| `Reload` | перезарядка |

Наведение делает моторика с ограниченной скоростью поворота ствола. Сеть выбирает, в кого и когда стрелять, а не управляет прицелом.

### `AgentView`, версия 1

Если меняется форма входа, сеть учится с нуля. Поэтому при изменении номер версии растёт.

- **`Self`**: позиция, скорость, взгляд и ствол, HP, стойка, вскинута ли винтовка, разброс, сведение, подавление, патроны, перезарядка, в кусте ли.
- **`Allies`** (≤ 9): точные позиции союзников, ближние первыми.
- **`Contacts`** (≤ 10): только враги, которых солдат видел, слышал или о которых ему сказали. Для каждого:
  - оценка позиции и скорости, высота прицела, неопределённость, возраст, источник (`See`, `Hear`, `Team`);
  - виден ли сейчас и какая доля тела видна, шкала обнаружения;
  - флаг «проверено — пусто»;
  - сидит ли, целится ли, целится ли в меня;
  - оценка шанса попадания `HitChance`.
- **`Cover`** (≤ 8): ближайшие точки укрытия с типом (низкое, высокое, куст, угол). Для каждой — сколько известных угроз увидят солдата там стоя и сидя, и занята ли она союзником.
- **`ExposedStand` / `ExposedCrouch`**: сколько известных угроз видят меня сейчас. Считается по своим контактам, а не по правде.
- **`Map`**: размер карты, своя и вражеская зоны появления, цель сценария.
- **Открытые числа**: `AlliesAlive`, `EnemiesAlive`, `TimeLeft`.

Контакты приходят с задержкой реакции `AgentSetup.ReactionDelay`, это кольцевой буфер видов. Собственное состояние приходит без задержки.

## Правила, числа по умолчанию

Все числа лежат в `Balance` и переопределяются из сценария (`"balance"`).

- **Тик 30 Гц.** Восприятие и решения ботов 10 Гц, агенты разнесены по фазе.
- **Движение** (из солдата):
  - шаг 1,45 м/с, бег 3,0, с прицелом 0,95, присед 0,85, присед с прицелом 0,6;
  - в кусте скорость ×0,75;
  - радиус тела 0,28 м, солдаты расталкиваются.
- **Винтовка** (`RIFLE` из `soldier-main.js`):
  - магазин 30, темп 800 выстр./мин;
  - разброс = база 0,0055 + (1 − сведение) × 0,075 + движение × 0,04 + поворот ствола × 0,03 + раскачка + подавление; сидя ×0,75;
  - сведение копится, пока стоишь и держишь прицел; теряется от выстрелов, движения, поворота и попадания по тебе;
  - вскидка 0,3 с — её задаёт симуляция, а не анимация;
  - перезарядка по фазам `RELOAD`: полная 1,72 с, тактическая 1,38 с, магазин выпадает на 0,17 с.
- **Пуля**:
  - 900 м/с, дальность 120 м;
  - за тик проверяется весь отрезок, так что пуля не проскакивает стену;
  - начинается из центра тела на высоте дула (стоя 1,45 м, сидя 0,9 м), поэтому через стену, к которой прижался, не выстрелить.
- **Хитбоксы** — три вертикальных цилиндра, которые зависят от стойки:
  - стоя: ноги до 0,9 м, корпус до 1,5 м, голова до 1,8 м;
  - сидя: 0,4 / 0,85 / 1,05 м;
  - урон: голова 100–120, корпус 30–42, ноги 18–26, HP 100.
- **Препятствия** — капсулы с высотой:

  | Тип | Высота |
  |---|---|
  | высокая стена | 2,5 м |
  | низкая стена / окно | 1,1 м |
  | ящик | 1,0 м |
  | дерево | 3 м |
  | куст | 1,4 м: скрывает (видимость × e^(−глубина/0,5)), но пули проходят |

  Луч перекрыт, если на входе или выходе из препятствия он ниже его высоты. Из этого получается:
  - стоя за низкой стенкой видны голова и грудь (2/3 точек);
  - сидя за ней тебя не видно, но и твой ствол ниже края стенки.
- **Восприятие**:
  - конус 120°, дальность 32 м;
  - видимость по трём точкам тела: стоя 0,5 / 1,15 / 1,65 м, сидя 0,3 / 0,65 / 0,95 м;
  - обнаружение копится от видимой доли, размера на дистанции, движения (бег ×3, неподвижность ×0,3) и места в конусе;
  - ошибка оценки дрейфует (процесс Орнштейна–Уленбека, 0,8° и 6% дальности, τ = 1,5 с) и падает до ×0,35, если смотреть на цель дольше 1 с;
  - слух: выстрел 40 м, бег 10 м, шаг 4 м, тихо 1,5 м, перезарядка 6 м; через стену радиус вдвое меньше;
  - пули, пролетевшие рядом, и попадания выдают стрелка;
  - контакты забываются через 25 с, «дошёл — пусто» помечает контакт;
  - по рации команды сведения приходят с задержкой 0,5 с.
- **Раунд**:
  - на выбывание с таймером;
  - флаги: `FriendlyFire` (по умолчанию выключен), `AlliesBlockBullets` (по умолчанию включён: свои останавливают пули);
  - `TimeoutWinner` и цель «дойти до зоны» (`ReachZone`, `ReachTeam`).

## Карты

- **Ручные** — `maps/*.json`:

  ```json
  { "name": "duel", "width": 24, "height": 30,
    "obstacles": [ { "kind": "lowwall", "a": [5, 9], "b": [9, 9] }, { "kind": "crate", "a": [11, 8] } ],
    "spawns": [[8, 1.5, 16, 3.5], [8, 26.5, 16, 28.5]],
    "zones": [{ "name": "goal", "at": [12, 37], "r": 2.5 }] }
  ```

  Виды: `highwall`, `lowwall`, `crate`, `bush`, `tree`. `r` и `h` по умолчанию берутся по виду.

- **Генератор** (`MapGen`). Сторона карты растёт с числом игроков: ~24 м для 1×1, ~41 м для 4×4, 60 м для 10×10.
  - Содержимое: дома с дверями и окнами, низкие стенки, ящики, кусты, деревья.
  - Режим `symmetric` (по умолчанию) отражает половину поворотом на 180°.
  - Карта принимается, только если зоны появления связаны, нет больших замкнутых карманов и после перекрытия коридора 3 м вокруг кратчайшего пути остаётся второй маршрут.
  - Параметры сценария: `density`, `buildings`, `foliage`, `lowCover`, `size`.

## Боты

`IBrain.Think(AgentView, Order, ref AgentAction, ref Rng)` вызывается при каждом обновлении вида. `BotRunner` держит действие между решениями, а нажатие `Single`/`Burst` подаёт один тик.

`Squad.Bots` видит симуляцию только через публичный `AgentView`, поэтому подсмотреть правду бот не может. Всевидение (`"omniscient": true`) — явный флаг для упражнений.

| Стратегия | Поведение |
|---|---|
| `dummy` | ходит туда-сюда, не стреляет |
| `turret` | стоит, бьёт всё, что видит, держит прицел на последнем контакте |
| `rusher` | бежит на ближайший контакт, стреляет на ходу, останавливается, если мажет |
| `holder` | пост в укрытии лицом к врагу, держит угол: выглянул — выстрелил — присел. `awareness` — как часто оглядывается (0 — никогда) |
| `rifleman` | от укрытия к укрытию к цели, выглядывает, отходит при низком HP, перебежки парами |
| `flanker` | уходит широко в сторону путём, невидимым для известных угроз, и заходит сбоку |
| `hunter` | идёт на свежие контакты и звуки, проверяет их, прочёсывает чужую половину |
| `marksman` | дальний пост, одиночные только после сведения, меняет позицию через 3 выстрела |
| `kiter` | держит дистанцию 13–24 м: отходит, стреляя, или сближается |
| `random`, `external` | случайные действия; действие задаётся снаружи (человек, сеть, тест) |

- **Сложность** `skill`: `easy`, `normal`, `hard`. Она задаёт задержку реакции, скорость ствола, шум восприятия, ошибку упреждения, частоту решений и порог шанса попадания. Разброс оружия — физика, он одинаков для всех.
- **`SquadTactic`** — командир на правилах, раз в 2 с:
  - общая цель: цель сценария для атакующих, иначе центр известных контактов или вражеская зона;
  - сбор растянувшегося отряда;
  - перебежки парами для riflemen (`MayMove`);
  - `Push`: если команда 20 с не стреляла и не получала попаданий, обороняющиеся тоже идут искать врага.

  Приказ `Order` — вход бойца, будущий интерфейс командира уровня 2.

## Сценарии

```json
{ "name": "asym-7v5", "map": { "gen": { "symmetric": true } }, "rules": { "roundTime": 180 },
  "balance": { "weapon": { "rpm": 750 } }, "randomizeBalance": 0.15, "tactics": true,
  "params": { "holder": { "awareness": 0 } },
  "teams": [ { "size": 7, "mix": { "rifleman": 3, "flanker": 2, "holder": 2 }, "skill": "normal" },
             { "size": 5, "mix": { "rifleman": 2, "marksman": 1, "holder": 1, "hunter": 1 }, "omniscient": false } ] }
```

- Если `mix` в сумме равен размеру команды, это точные количества. Иначе это веса.
- `"randomSizes": [1, 10]` задаёт случайные размеры команд в каждом матче.
- `"learner": 0` помечает слот будущей сети. Пока его играет бот на правилах.

| Сценарий | Зачем |
|---|---|
| `aim-dummies` | стрельба по манекенам |
| `duel-turret` | 1×1 против неподвижного стрелка |
| `cross-under-fire` | дойти до зоны под огнём турели: перебежки |
| `survive-15s` | продержаться 15 с против двоих: прятаться и приседать |
| `hide-seek` | прятки в густых кустах против двух охотников |
| `flank-forward-defenders` | защитники смотрят только вперёд: обход окупается |
| `team-4v4-mixed`, `asym-4v6`, `asym-7v5`, `big-10v10` | командные бои |
| `random-composition` | размеры 1..10 случайно, стратегии по весам |

## Детерминизм и реплеи

- Одинаковые конфиг и действия дают бит в бит тот же матч.
- `DMath` использует только + − × ÷ и `sqrt`. CRT Windows и Linux дают разные последние биты `Math.Sin` и `Math.Exp`, поэтому библиотечные функции в правилах не используются.
- Генераторы случайных чисел PCG32 хранятся в матче: свой поток у мира и у шума восприятия каждого солдата.
- Обход только массивами по индексу, без потоков внутри матча. Параллельно идут матчи.
- Реплей хранит заголовок с полным конфигом (числа точные), действия всех тиков и хэш каждую секунду. `verify` пересчитывает и сверяет.
- Тест `BitsAreStable` хранит эталонные биты `DMath`. Если на другой ОС он упадёт, реплеи оттуда не сойдутся.
- **Проверка на ПК**: `replay record` в облаке, затем `replay verify` на Windows.
- `Match.Place` (тесты) в реплей не пишется.
- `Step` не выделяет память (тест и `bench`).

## Замеры

Linux x64, одно ядро на матч. Арена грузит все ядра.

| Состав | Симуляция, мкс/тик | С ботами | Быстрее реального времени |
|---|---|---|---|
| 1×1 | ~10–30 | ~10–30 | > 1000× |
| 4×4 | ~25 | ~28 | ~1300× |
| 7×5 | ~85 | ~85 | ~400× |
| 10×10 | ~80–150 | ~80–155 | ~220–400× |

Аллокаций в шаге 0 байт. Арена на 4 ядрах гоняет 4×4 в ~2000 раз быстрее реального времени.

**Матрица стратегий** 3×3, по 60 матчей на пару (`crosstab`), счёт строки против столбца:

| | rusher | holder | rifleman | flanker | hunter | marksman | kiter | в среднем |
|---|---|---|---|---|---|---|---|---|
| rusher | — | 25 % | 34 % | 57 % | 7 % | 54 % | 20 % | 33 % |
| holder | 75 % | — | 63 % | 37 % | 35 % | 51 % | 52 % | 52 % |
| rifleman | 66 % | 37 % | — | 28 % | 22 % | 27 % | 15 % | 32 % |
| flanker | 43 % | 63 % | 72 % | — | 38 % | 60 % | 33 % | 52 % |
| hunter | 93 % | 65 % | 78 % | 62 % | — | 57 % | 57 % | 69 % |
| marksman | 46 % | 49 % | 73 % | 40 % | 43 % | — | 60 % | 52 % |
| kiter | 80 % | 48 % | 85 % | 67 % | 43 % | 40 % | — | 61 % |

Абсолютного лидера нет. Есть циклы «камень-ножницы-бумага», например holder > rusher > flanker > holder. Значит, сети есть у кого учиться и нет одного контрприёма на всех.

**Неравные составы** (`random-composition`, 400 матчей), счёт команды A по разнице в людях:

| A − B | −4 | −3 | −2 | −1 | 0 | +1 | +2 | +3 | +4 |
|---|---|---|---|---|---|---|---|---|---|
| счёт A | 1 % | 7 % | 22 % | 35 % | 65 % | 77 % | 71 % | 94 % | 94 % |

## Что уже показала арена

- **Две обороняющиеся стороны сидят вечно.** Последние holder и marksman держали посты до таймаута в 22% матчей 4×4.
  - Лечение — `Push` у командира по отсутствию боя, а не по отсутствию контакта.
  - Мелькание врага не считается боем. Иначе стороны выходят, видят друг друга, сбрасывают флаг и расходятся по постам.
  - После правки таймаутов в 4×4 и 7×5 ~1%, в 10×10 ~10%.
- **Шум восприятия 1,5° из `bots.md` больше разброса винтовки** (0,3°): на 23 м промах ~0,6 м, дальний бой исчезает. Принято 0,8° и ×0,35 после «присмотрелся».
- **Стрельба на ходу почти не попадает** (раскачка от движения). Rusher без остановок имел точность 6% и K/D 0,14. Теперь он останавливается, если мажет.
- **Обороняющийся сведённый стрелок сильнее наступающего.** Turret выигрывает у rifleman ~85%. Это заложено в `bots.md` (5.6, п. 4) и делает выгодными обход и перебежки.
- **Перевес в людях решает почти всё.** Уже при ±2 исход почти предрешён. Для обучения на неравных составах нужны режимы с преимуществом обороны (атака/оборона точки), а критику — численность команд на входе.

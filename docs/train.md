# Обучение ботов (PPO)

Итерация 2 плана из [`bots.md`](bots.md). Нейросеть учится играть солдатом в симуляции [`sim/`](sim.md). Соперники — боты на правилах, они работают внутри той же библиотеки.

Цель итерации: первый обученный бот, который проходит упражнения и обыгрывает ботов на правилах в 1×1.

## Как устроено

```
Python (train/)                                  libsquad.so (sim/Squad.Train, Native AOT)
  PPO, сеть, оптимизатор (GPU)   ── ctypes ──▶     VecEnv: N матчей на всех ядрах CPU
  буферы numpy без копий         ◀── указатели ──   слоты ученика ← действия сети
                                                     остальные солдаты ← боты на правилах (BotRunner)
```

- **Нативная библиотека.** Симуляция, боты и среда обучения собираются Native AOT в одну `.so` (~3 МБ). Python вызывает её через ctypes, процессов и сериализации нет.
- **Шаг среды.** Один шаг = одно решение = 3 тика (10 Гц). Закончившийся матч сразу начинается заново (семантика gymnasium: вход после `done` — первый вход нового эпизода).
- **Соперники бесплатны для Python.** Это `BotRunner` внутри библиотеки.
- **Детерминизм.** Одинаковые конфиг, seed и действия дают те же входы бит в бит. Любой эпизод можно записать в реплей и посмотреть (`render --replay`).

### Вход сети (версия 1, 465 чисел)

Строится только из `AgentView`. Всё в системе ствола солдата: x вправо, y вдоль ствола. Масштабы фиксированы в коде (`Squad.Train/Codec.cs`).

| Блок | Размер | Что внутри |
|---|---|---|
| своё | 42 | скорость, корпус относительно ствола, HP, стойка, прицел, вскидка, перезарядка, разброс, сведение, подавление, патроны, открытость, время, живые; направления на свою/чужую зону и цель; приказ; размер карты |
| союзники | 9 × 10 | позиция, расстояние, скорость, курс, HP, стойка, прицел |
| контакты | 10 × 21 | позиция, пеленг от ствола, скорость, высота прицела, неопределённость, возраст, источник, виден ли, доля, обнаружение, «пусто», сидит/целится/в меня, шанс попадания |
| укрытия | 8 × 12 | позиция, нормаль, тип, угол, занято, угрозы стоя/сидя |
| флаги присутствия | 9 + 10 + 8 | какие слоты заполнены |

### Действия (6 голов, маски недопустимого)

| Голова | Варианты |
|---|---|
| движение (19) | стоп · 8 направлений от ствола · к первому контакту · к цели · к укрытию k |
| режим (3) | шаг / бег / крадучись |
| стойка (2) | стоя / сидя |
| прицел (11) | опустить · контакт k |
| спуск (4) | нет / одиночный / очередь / авто |
| перезарядка (2) | нет / да |

- Нажатие спуска и перезарядка подаются на один тик.
- Ствол наводит моторика симуляции с ограниченной скоростью поворота, поэтому аимбота нет.
- Если меняется форма входа или выхода, растут `Obs.Version` и `Act.Version`. Чекпоинты старой версии не загрузятся.

### Сеть (`train/squad/model.py`, 0,34 млн параметров)

- **Своё** — MLP. **Союзники, контакты, укрытия** — общие MLP на сущность и маскированные mean+max пулы.
- **Ствол** — MLP 256, по желанию GRU (`"recurrent": true`).
- **«К укрытию k» и «прицел на контакт k»** — указательные головы: запрос из состояния против встраивания каждой сущности. Слоты пересортировываются каждое решение, поэтому их номер не должен ничего значить.

### PPO (`train/squad/ppo.py`)

- **Стиль CleanRL:** GAE (γ 0,995, λ 0,95), clip 0,2, энтропия 0,01 → 0,002, lr 3e-4 → 3e-5. Rollout 128 шагов, 4 эпохи, 8 минибатчей.
- **Мёртвые слоты** (`alive = 0`) не являются решениями и в лосс не идут. Смерть и конец матча обрывают цепочку преимуществ.
- **Награда** из секции `"reward"` сценария:
  - исход: победа +1, поражение −1, ничья;
  - подсказки: урон, убийства, смерть. Они умножаются на коэффициент, который за долю `shapingAnneal` стадии гаснет до 0, чтобы бот учился побеждать, а не набивать очки;
  - штраф за время (не гаснет).
- **Программа обучения** `train/configs/curriculum-1v1.json`. Стадия заканчивается, когда процент побед за последние 400 эпизодов ≥ `promote` (не раньше `minSteps`) или кончился бюджет шагов:

  | Стадия | Сценарии | Порог | Бот на правилах на месте ученика (база) |
  |---|---|---|---|
  | `aim` | `train-aim`: три манекена | 90 % | 78 % побед |
  | `turret` | `train-turret-easy` + `train-turret` | 60 % | 30 % / 6 % |
  | `duel` | `train-duel` (карта duel) + `train-duel-gen` (сгенерированные, баланс ±10 %) против смеси rifleman/holder/hunter/kiter/marksman/flanker | 75 % | 50 % / 54 % |

  Базу получить так: `Squad.Tools arena --scenario sim/scenarios/train-*.json` — там ученика играет rifleman.

## Запуск в облаке

Нужно: Linux x64, Python 3.10+, PyTorch с CUDA, .NET 8 SDK и clang (только для сборки библиотеки).

```sh
git clone … && cd iso-knight
./train/build_native.sh                 # → train/native/squad.so (собирать на этой же машине или на Linux не новее: glibc)
pip install -r train/requirements.txt    # torch под драйвер видеокарты, numpy
python train/tests/smoke.py              # формы, NaN, детерминизм, шагов/с без сети
python train/train.py --config train/configs/curriculum-1v1.json --device cuda:0 --run runs/c1
```

**Две T4.** Сеть маленькая, GPU не узкое место, узкое место — ядра CPU под симуляцию. Поэтому запускать два независимых обучения:

```sh
python train/train.py --config train/configs/curriculum-1v1.json --device cuda:0 --seed 1 --threads 8 --run runs/a &
python train/train.py --config train/configs/curriculum-1v1.json --device cuda:1 --seed 2 --threads 8 --run runs/b &
```

`--threads` — ядра симуляции на запуск; поделить ядра машины пополам.

Полезные ключи:

| Ключ | Что делает |
|---|---|
| `--stage duel --resume runs/a/stage-turret.pt` | продолжить с нужной стадии |
| `--steps 3e6` | свой бюджет шагов |
| `--envs 256` | больше параллельных матчей: больше шагов/с, если хватает ядер |

## Что смотреть

- **Консоль и `runs/<имя>/log.txt`** раз в 5 обновлений: шаги/с, процент побед и ничьих по сценариям, длина эпизода, энтропия, KL, ошибка ценности, объяснённая дисперсия (`ev`), текущий коэффициент подсказок.
- **`runs/<имя>/metrics.jsonl`** — то же построчно в JSON, для графиков.
- **Чекпоинты:** `latest.pt` раз в 50 обновлений, `stage-<имя>.pt` в конце стадии.
- **Оценка на отложенных seed'ах** (не встречались в обучении):

  ```sh
  python train/eval.py --checkpoint runs/a/latest.pt --scenario sim/scenarios/train-duel-gen.json --matches 400 --device cuda:0
  python train/eval.py --checkpoint runs/a/latest.pt --scenario sim/scenarios/train-aim.json --record out/aim --record-count 4
  dotnet run --project sim/Squad.Tools -c Release -- render --replay out/aim/ep0.rpl --every 3
  ```

- **Признаки проблем:**

  | Признак | Что значит |
  |---|---|
  | энтропия падает до ~0 сразу | слишком маленький коэффициент энтропии или слишком большой lr |
  | `kl` > 0,05 | шаги слишком большие |
  | `ev` около 0 долго | ценность не учится, проверить награду |
  | побед нет, ничьих 100 % | бот не находит врага, нужна стадия проще или подсказки дольше |

## Замеры (контейнер, 4 ядра, CPU без GPU)

| Что | Скорость |
|---|---|
| только среда, случайные действия (`smoke.py`) | 36–53 тыс. шагов агента в секунду |
| сбор опыта с сетью на CPU, 64 матча | ~9–15 тыс. шагов/с |
| обучение целиком на CPU | ~3,9 тыс. шагов/с (узкое место — обновление PPO на CPU) |

На T4 обновление почти бесплатно. Ожидаемо: при 8 ядрах на запуск и 128–256 матчах 15–30 тыс. шагов/с, то есть 50–100 млн шагов за сутки на запуск.

## Подводные камни, которые уже встретились

| Камень | Что было | Решение |
|---|---|---|
| Native AOT обрезает метаданные | `RewardSpec has no field 'win'`: JSON награды применяется рефлексией | `TrimmerRootAssembly` для всех трёх сборок; ошибка дошла до Python текстом, а не падением процесса |
| PyTorch с PyPI без CUDA-библиотек не импортируется даже для CPU | — | в облаке ставить сборку под драйвер; локально — полный пакет (~5 ГБ) |
| Повторное `Single` без отпускания не стреляет | — | спуск подаётся на один тик, на остальных тиках решения снимается |
| Слабый сигнал в начале | случайная политика наносит ~60 урона за 45 с, побед почти нет | у стадии `aim` награда за урон и убийство выше; интерфейс проверен скриптом «целься в первый контакт, стреляй» — 66 % побед через тот же API |

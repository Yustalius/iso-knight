# Умные боты на нейросетях — итоги обсуждения

Конспект проектного обсуждения: как строить игру, чтобы в ней могли жить боты на нейросетях.
Концепция игры пока условная: два отряда (игрок с ботами против ботов, либо люди против ботов),
изометрия, стрельба. Кода по этому документу ещё нет.

Документ разбит на три части:

- **Основа.** Движок, механики, честность. Нужна при любом варианте ботов.
- **Уровень 1.** Бойцы без командира. Проще, делается первым.
- **Уровень 2.** Командир отряда. Добавляется поверх уровня 1.

---

## 1. Главные принципы

1. **Скорость нейросети — не проблема.**
   - Боту хватает 10–15 решений в секунду. Так работают OpenAI Five (~7,5 Гц), DeepMind FTW в Quake III (~15 Гц), GT Sophy (10 Гц).
   - Сеть на 0,1–1 млн параметров считается за доли миллисекунды даже на чистом JS.
   - 8 ботов по 10 решений в секунду — меньше 1% CPU.
2. **Реальные проблемы в другом:**
   - обучение дорогое: нужен очень быстрый прогон игры без графики;
   - сверхчеловеческая реакция и аимбот;
   - бота трудно контролировать и отлаживать;
   - каждый баланс-патч требует дообучения;
   - сильный бот ≠ интересный бот.
3. **Бот умный ровно настолько, насколько ум выгоден по правилам игры.** Нужное поведение получаем через условия: механики, карты, противников, сценарии. Награду не трогаем. Если лобовая атака работает не хуже обхода, обхода не будет никогда.
4. **Сети не нужны понятия** вроде «укрытие» или «стелс». Она видит числа и учится на последствиях: здесь в меня не попадают, здесь меня не замечают.
5. **Сеть решает «что, когда, в кого». Код решает «как»:** путь, наведение, отдача.
6. **Фиксировать нужно интерфейс**, то есть что бот видит и какие у него действия. Не числа баланса. Поменялась форма входа или выхода — сеть учится с нуля. Поменялись числа — хватает дообучения или вообще ничего, если числа рандомизировались при обучении.
7. **Человек и бот играют по одним правилам:** одинаковые видимость, разброс, скорость поворота ствола, туман войны.

## 2. Слои решений

| Слой | Частота | Кто решает | Что решает |
|---|---|---|---|
| Стратегия / командир | раз в 2–3 с | уровень 1: скрипт или приказ игрока; уровень 2: сеть-командир | куда идти отряду, кому разведка, кому держать, когда собраться и ударить |
| Тактика | 10 Гц | **нейросеть бойца** | шаг, стрейф, присесть, выглянуть, к какому укрытию идти, кого выбрать целью, когда и как стрелять, отступить |
| Моторика | 30–60 Гц | код | путь по навмешу, поворот ствола с ограничением, упреждение, сведение, отдача, анимация |

Приказ сверху — один из входов тактической сети. Поэтому один и тот же боец работает и с командиром-скриптом, и с командиром-сетью, и с приказами игрока.

## 3. Основа: движок и симуляция

Делается до любого обучения. Обучение без быстрой и честной симуляции невозможно.

### 3.1 Требования к ядру `sim/`

- **Логика отдельно от отрисовки.** Модуль `sim/` на чистом JS, без three.js и DOM. `step(state, actions)` возвращает новое состояние и события. Отрисовка только читает состояние.
- **Фиксированный шаг симуляции**, например 30 Гц. Отрисовка сглаживает между шагами. Бот решает раз в несколько шагов.
- **Детерминизм.** Генератор случайных чисел с seed хранится в состоянии. Реплей = seed + лог действий. Реплеи нужны для отладки, для просмотра партий из обучения в браузере и для обучения на партиях человека.
- **Один API для человека и бота.** Клавиатура и мышь выдают ту же структуру действия, что и сеть. Партии человека сразу становятся данными для имитации.
- **Восприятие внутри симуляции.** Видимость, звук, память. Бот получает только то, что видел бы его солдат.
- **Логика в 2D, графика в 3D.** Позиции на плоскости, у препятствий есть высота. Проверки дешёвые, наблюдения маленькие.
- **Скорость.** Тик матча 4×4 должен занимать десятки микросекунд, то есть игра идёт в тысячи раз быстрее реального времени на одном ядре. В горячем цикле ничего не создаём (`new`, `clone()`), соседей ищем по сетке.
- **Карты — это данные плюс процедурная генерация.** Иначе боты заучат одну карту.
- **Отладочный оверлей.** Что бот видит, какие у него вероятности действий, какую оценку ситуации даёт сеть.
- **Бот на правилах.** Нужен как первый соперник, как эталон для сравнения и как запасной вариант.

Эскиз API:

```js
const match = createMatch({ seed, map, teams, config });
step(match, actions);            // actions[id] = { move, stance, target, trigger, ... }
const obs = observe(match, id);  // только то, что агент видит, слышит и помнит
```

### 3.2 Что мешает в текущем прототипе

| Место | Проблема | Как должно быть |
|---|---|---|
| `src/main.js` `update()` | логика смешана с камерой, частицами, DOM | логика в `sim/`, остальное в отрисовке |
| `src/main.js` `loop()` и `update()` | шаг времени зависит от кадров, hitstop и slowmo меняют время симуляции | фиксированный шаг; hitstop и slowmo — эффекты отрисовки |
| `src/main.js` `doHit()` | урон через `Math.random()` | генератор с seed в состоянии |
| `src/main.js` `update()` | движение задаётся в осях камеры | симуляция принимает мировые команды, пересчёт из камеры — у ввода человека |
| `src/main.js` `collide()` | алгоритм годится, но живёт в `main.js` | переехать в `sim/` |
| `src/world.js` коллайдеры | плоские капсулы без высоты | добавить высоту `h` и флаги `sight` / `bullets` |

## 4. Основа: механики восприятия и боя

Общие для людей и ботов. Определяют, что бот видит, поэтому появляются до обучения.

### 4.1 Видимость и укрытия (2.5D)

У препятствия есть высота и флаги:

```js
{ ax, az, bx, bz, r, h: 0.9, sight: true,  bullets: true  }  // низкая стенка, ящик
{ ax, az, bx, bz, r, h: 2.5, sight: true,  bullets: true  }  // стена, ствол дерева
{ ax, az, bx, bz, r, h: 1.4, sight: true,  bullets: false }  // куст: прячет, но не защищает
```

У персонажа есть высота глаз и контрольные точки тела:

| Стойка | Глаза | Точки тела |
|---|---|---|
| стоя | 1,6 м | 0,5 / 1,1 / 1,6 м |
| сидя | 1,0 м | 0,4 / 0,8 / 1,0 м |

**Проверка видимости.** Из глаз A проводим лучи в каждую точку тела B. Для каждого препятствия находим вход и выход луча на плоскости (`t1`, `t2`). Высота луча меняется по прямой, поэтому луч перекрыт, если `min(y(t1), y(t2)) < h`.

Результат — **видимая доля тела**. Пули проходят ту же проверку и попадают только в видимые точки. Персонажи линию видимости не перекрывают.

Что из этого получается:

- **стоя за низкой стенкой:** видны голова и плечи, это частичное укрытие;
- **сидя за низкой стенкой:** тебя не видно, но и стрелять нельзя. Нужно встать. Так появляется «выглянул — выстрелил — спрятался»;
- **высокая стена:** закрывает полностью, стрелять можно только из-за угла;
- **куст:** не видно, но очередь вслепую пройдёт насквозь.

Дополнительно:

- **Конус обзора** около 120°. Сзади слепая зона.
- **Звук.** Бег слышно на ~10 м, шаг на ~4 м, крадучись почти не слышно, выстрел на ~40 м. Звук даёт направление с ошибкой.
- **Предрасчёт видимости.** Карта статичная, поэтому видимость «клетка → клетка» для пар высот можно посчитать при загрузке: для арены 30×30 м с клетками 1 м это меньше мегабайта. Тогда открытость — поиск в таблице.

### 4.2 Дальность: хуже видно

**Ошибка восприятия.** Бот получает оценку позиции врага, а не точную позицию:

- угловая ошибка постоянная, около 1,5°, поэтому промах в метрах растёт с дистанцией: на 5 м ~13 см, на 30 м ~0,8 м;
- ошибка по дальности — 5–10% дистанции;
- ошибка **медленно дрейфует**, а не перебрасывается каждый тик;
- пока смотришь на цель, ошибка уменьшается («присмотрелся»);
- ошибка растёт, если цель бежит, видна частично или сидит в кусте.

**Обнаружение с накоплением.** Заметность складывается из:

- видимой доли тела;
- углового размера цели (падает с дистанцией);
- движения: бег ×3, неподвижность ×0,3;
- куста;
- центр конуса обзора или периферия.

Заметность копится в шкалу: сначала «там что-то есть» (контакт с большим радиусом неопределённости), потом «вижу врага». Неподвижного бойца в кусте вдалеке можно не заметить вовсе. Это фундамент стелса.

### 4.3 Память: контакты и последняя известная позиция

Память явная, в слое восприятия. Рекуррентная память сети (GRU) её дополняет, но не заменяет.

```js
contacts[enemyId] = { x, z, vx, vz, seenAt, src /* see | hear | team */, visibleNow, uncertainty }
```

Правила:

- **видим** — обновляем всё;
- **пропал** — запись остаётся, неопределённость растёт как скорость × время с момента обнаружения;
- **услышали** — позиция с шумом, `src = 'hear'`;
- **дошли до точки, а там пусто** — контакт устаревает. Без этого правила бот вечно держит пустой угол;
- **через 20–30 с** контакт забывается;
- **союзники делятся контактами** по «рации» с небольшой задержкой.

Радиус неопределённости контакта и ошибка восприятия из 4.2 — одно и то же поле.

### 4.4 Прицел и сведение

Прицел — состояние оружия в симуляции, а не выход сети:

```js
aim = { yaw, spread, targetId }
```

Скрипт моторики каждый тик:

- **поворачивает ствол** к оценке позиции цели (плюс упреждение) с ограниченной скоростью;
- **раскачивает разброс** от бега и ходьбы, от резкого поворота ствола, от каждого выстрела, от попадания по тебе и по желанию от подавления (пуль, пролетевших рядом);
- **сводит разброс** к базовому, пока стоишь, сидишь и держишь цель: `spread = base + (spread - base) * exp(-dt / settleTime)`.

Выстрел летит в направлении `aim.yaw + gauss(rng) * spread` и проходит ту же проверку видимости. Пуля летит не мгновенно, поэтому по бегущей цели вдалеке нужно упреждение, и оно тоже с ошибкой.

Подавление стоит включить: оно делает выгодной связку «один прижимает огнём, второй обходит».

### 4.5 Честность для человека

- Человек тоже видит туман войны и сектор обзора, как в Door Kickers или Darkwood.
- **Ортокамера не уменьшает дальние объекты.** Враг на 25 м на экране такой же, как на 5 м. Поэтому сложность дистанции заложена в правилах (разброс, сведение) и в отрисовке: не до конца замеченный враг показывается размытым маркером.
- Бот не видит дальше, чем помещается на экране игрока.
- Курсор задаёт желаемое направление. Ствол поворачивается к нему с той же ограниченной скоростью, резкий рывок мышью тоже раскачивает разброс.
- **Круг разброса у курсора**, как в World of Tanks. По информации это то же самое, что оценка шанса попадания у бота.

## 5. Уровень 1: бойцы без командира

Стратегию задаёт скрипт или приказ игрока. Каждый боец — тактическая нейросеть.

### 5.1 Что видит сеть бойца

- **Своё состояние:** здоровье, стойка, скорость, патроны, перезарядка, разброс.
- **Союзники и контакты** — списки сущностей. Видимые и запомненные враги — один объект с флагами «виден сейчас», «сколько секунд назад», «неопределённость», «источник». Плюс смотрит ли враг на меня и свёлся ли он: ствол врага видно, информация честная.
- **Точки укрытия.** Генерируются вдоль краёв препятствий при загрузке карты. Боту даются 8 ближайших, у каждой:
  - расстояние по пути;
  - тип (низкое, высокое, куст);
  - от скольких известных угроз точка закрыта стоя и сидя;
  - можно ли отсюда выглянуть и стрелять.

  Это главный ускоритель обучения.
- **Своя открытость:** от скольких известных мне угроз есть линия видимости до меня, стоя и сидя. Точное «меня сейчас видят» давать нельзя — это чит.
- **Локальная сетка** около 12×12 клеток по 0,5–1 м вокруг бота. Каналы: препятствия по типам, открытость клеток, союзники, контакты.
- **Грубая карта всей арены**, например 32×32: стены, контакты, свои. Без неё бот не знает о других маршрутах и не сможет обходить.
- **Качество прицела:** разброс, ошибка наведения, угловой размер видимой части цели и одним числом оценка шанса попадания:
  `pHit = Φ((θ − e)/σ) − Φ((−θ − e)/σ)`, где `σ = sqrt(spread² + σ_восприятия²)`.
- **Приказ сверху:** район и режим.

### 5.2 Что выдаёт сеть бойца

| Выход | Варианты |
|---|---|
| Движение | направление и скорость, либо «иди к точке укрытия i» |
| Стойка | стоя / сидя |
| Цель | указатель на любой контакт, **включая невидимый** (так появляется «держать угол»), или никто |
| Спуск | не стрелять / одиночный / очередь 3 / огонь без остановки |
| Точка на цели (по желанию) | корпус / голова |

Прямое управление прицелом сетью не делаем: обучение сильно усложняется, а результат уходит в аимбот или дёрганый прицел.

### 5.3 Устройство сети

- **Своё состояние** — небольшая полносвязная сеть (MLP).
- **Списки сущностей** — общий MLP и attention или pooling. Работает при любом числе юнитов.
- **Сетка и карта** — маленькая свёрточная сеть.
- Затем **GRU на 256** и отдельные выходы на каждое действие, плюс оценка ситуации.
- Всего ~0,3–1 млн параметров. В браузере — свой код вывода или ONNX Runtime Web.

### 5.4 Обучение

- **Инфраструктура.** Симуляция в Node-воркерах, по 64–256 матчей на процесс. Обучение в Python + PyTorch, связь по бинарному каналу. За основу — CleanRL или Sample Factory. Перенос ядра на Rust/WASM — только если упрёмся в скорость.
- **Алгоритм.** PPO с GRU. Для команды — MAPPO: оценщик при обучении видит всё поле, сам боец только своё.
- **Противники.** Игра против себя с пулом прошлых версий, позже лига с «эксплойтерами».
- **Награда.** Победа плюс подсказки: урон, убийства, смерти, цель карты. Подсказки постепенно ослабляются.
- **Длинный горизонт:** коэффициент дисконтирования γ = 0,995–0,999.
- **Рандомизация баланса** ±15% при обучении: скорости, урон, разброс. Тогда мелкие правки баланса не требуют переобучения.
- **После изменений** дообучаем с текущих весов, а не учим с нуля.
- **Имитация.** Несколько часов записей твоих партий дают стартовые навыки, например обход. Дальше обучение с подкреплением шлифует.
- **Ориентир по объёму (грубо):** при десятках тысяч шагов в секунду 100 млн шагов — около часа. Для 1×1 хватит десятков миллионов, командная тактика — сотни миллионов и больше.

### 5.5 Программа обучения и сценарии

Основная лестница: цели-манекены → 1×1 против бота на правилах → 1×1 против себя с укрытиями → 2×2 → 4×4 на случайных картах.

Сценарии-упражнения:

- «Добеги до точки, пока турель стреляет во всё, что видит» — перебежки между укрытиями.
- «Продержись 15 секунд против двух стрелков» — прятаться и приседать.
- Прятки: один прячется, другой ищет — разрывать линию видимости и искать по последней точке.
- Обход: сначала короткий и очевидный, потом длиннее. Генератор карт подстраивает сложность под бота (Prioritized Level Replay).
- Противники с изъяном на старте: скриптовые защитники смотрят только вперёд. Потом игра против себя — гонка вооружений, как в прятках OpenAI.

### 5.6 Условия, при которых выгодны стелс и обход

1. Укрытие защищает только с одной стороны, с фланга ты открыт.
2. Конус обзора и обнаружение с накоплением: со спины замечают поздно.
3. Застигнутый врасплох тратит время на реакцию, разворот и сведение. Обычно этого достаточно, бонус урона в спину не нужен.
4. Оборона в лоб сильна: сидящий за укрытием сведённый стрелок выигрывает у бегущего на него.
5. Звук: бег громкий, крадучись тихо, но медленно.
6. На картах несколько маршрутов.
7. Есть цель, таймер и роли «атака» / «оборона».

### 5.7 Какое поведение ожидаем на уровне 1

- Прятаться, приседать, выглядывать и стрелять.
- Ждать, пока враг отвернётся, подкрадываться, обходить ящик или дом.
- Держать угол, где пропал враг, и заранее сводиться туда.
- Вдалеке — остановиться, присесть, стрелять одиночными. Вблизи по неготовому врагу — стрелять сразу.
- Не высовываться, если враг уже свёлся.
- Не дёргать ствол между целями.
- Если включено подавление, пара «один прижимает, второй обходит».
- **Обход через полкарты** возможен, только если стратегический слой выдаёт маршрут: «тихо выйти в район X». Тогда это 3–5 решений вместо 400.

### 5.8 Сложность и человечность

- **Разброс — физика оружия**, одинаковая для всех. Его не трогаем.
- **Ручки сложности:**
  - задержка реакции (бот видит мир на 150–250 мс в прошлом);
  - скорость поворота ствола;
  - шум восприятия;
  - точность упреждения;
  - ограничение частоты действий.
- **Уровни:** версии весов разной силы (слабый / средний / сильный) плюс параметры моторики.

## 6. Уровень 2: командир отряда

### 6.1 Зачем

Плоский вариант — каждый боец сам по себе, общая награда, общие контакты. У OpenAI Five так выросла командная игра, но на тысячах видеокарт. На наших мощностях будет максимум «держаться вместе и прикрывать». Разведку, разделение на группы, сбор и удар нужно делать через командира.

### 6.2 Устройство

- **Отдельная сеть**, решает раз в 2–3 секунды.
- **Видит общую картину отряда:** грубую карту, все контакты с неопределённостью, состояние и позиции бойцов, время, цель.
- **Каждому бойцу выдаёт приказ:** район и режим — `разведка`, `скрытно выдвинуться`, `держать`, `атаковать`, `собраться`.
- **Бойцы — сеть уровня 1** с приказом на входе. Каждый выполняет приказ по-своему.
- **За матч около 50 решений**, а не десятки тысяч. Поэтому командир может выучить порядок «разведать → собраться → ударить».
- **Плана как отдельной структуры нет.** Рекуррентная память командира помнит, что уже разведано и кто куда послан. План — это серия приказов, которая чаще выигрывает.

### 6.3 Когда появится разведка

Нужны три условия:

- туман войны;
- общие контакты отряда;
- **случайные позиции врага.**

Если враг всегда стоит в одном месте, разведка не нужна и не появится.

### 6.4 Порядок обучения

1. **Бойцы учатся выполнять случайные приказы.** Награда за выполнение приказа нужна — это стандартная часть иерархического обучения и честное исключение из правила «награду не трогаем». Командная победа остаётся в награде.
2. **Командир на правилах** (правила или планировщик). Сразу даёт осмысленную командную игру и соперников для обучения.
3. **Нейросетевой командир** учится побеждать командира на правилах, затем играет против себя.

### 6.5 Бонусы

- Игрок может быть командиром своего отряда. Интерфейс приказов тот же.
- Приказы видны, поэтому понятно, что задумали боты. Их можно выводить как переговоры по рации: «Двое — разведка слева».
- Сложность настраивается раздельно: умный командир с косыми бойцами или наоборот.

## 7. Подводные камни

### Движок

| Камень | Чем лечим |
|---|---|
| Логика завязана на кадры, hitstop или slowmo, `Math.random()` — нет детерминизма и реплеев | фиксированный шаг, генератор с seed в состоянии, эффекты только в отрисовке |
| Создание объектов в горячем цикле убивает скорость обучения | плоские числа и типизированные массивы, сетка соседей |
| Предрасчёт видимости ломается с разрушаемыми укрытиями | частичный пересчёт при разрушении |

### Честность и восприятие

| Камень | Чем лечим |
|---|---|
| Враг за стеной попадает во входы бота — сеть научится видеть сквозь стены | автотест на протечки информации |
| Точный признак «меня сейчас видят» — это чит | открытость считается по своим контактам |
| Оценщик со всей картой (MAPPO) | допустим только при обучении, в игре его нет |
| Шум восприятия каждый тик новый — сеть его усреднит | ошибка медленно дрейфует |
| Контакт не очищается — бот вечно держит пустой угол | «проверил — пусто» помечает контакт устаревшим |
| Ортокамера: для человека дальность не сложнее | сложность в правилах и размытые маркеры |
| Бот видит дальше экрана человека | дальность восприятия ≤ видимой части экрана |
| Прицел у сети — аимбот или дрожь, тяжёлое обучение | наведение в коде, сеть выбирает цель и момент |

### Обучение

| Камень | Чем лечим |
|---|---|
| Сверхчеловеческая реакция | задержка наблюдений, ограничение поворота и частоты действий |
| Подсказки в награде — бот набивает очки вместо победы | ослаблять подсказки, основная награда — победа |
| Награда за укрытие — вечный кемпер | за укрытие не награждать, оно окупается само |
| Заучил одну карту | процедурные карты, случайные точки появления |
| Стратегии ходят по кругу | пул прошлых версий, лига |
| Длинный горизонт и исследование: обход не находится | иерархия, сценарии, большой γ, имитация |
| Изменился интерфейс — учить с нуля | заморозить форму входов и выходов заранее |
| Изменились числа баланса | рандомизация при обучении, дообучение |

### Игровой дизайн и команда

| Камень | Чем лечим |
|---|---|
| Лобовая атака не хуже обхода — обхода не будет | условия из 5.6 |
| Обе команды сидят и ждут, ничья безопаснее риска | цель, таймер, роли атака/оборона, таймаут = поражение атакующих |
| Разведка не появляется | случайные позиции врага, туман войны |
| Бот играл только с копиями себя и теряется с живым игроком (Overcooked, 2019) | разные партнёры: прошлые версии, скрипты, модель человека; приказы игрока на входе |
| Сильный ≠ интересный | ручки моторики, уровни сложности, плейтесты |
| Плоская сеть не выучит разведку и сбор | командир (раздел 6) |

## 8. План работ

1. **Минимальные механики**, важные для ботов: HP, оружие, укрытия, присед, видимость.
2. **Ядро `sim/`:**
   - детерминированное, с фиксированным шагом, без графики в Node, с реплеями;
   - отрисовка — просмотрщик, человек управляет через тот же API;
   - видимость с высотами и отладочная отрисовка (сектор обзора, лучи);
   - контакты и звук, шум восприятия и обнаружение;
   - прицел и сведение.
3. **Бот на правилах** и замер скорости симуляции.
4. **Обёртка для обучения** (reset/step), связь с Python, PPO 1×1, просмотр реплеев из обучения.
5. **Игра против себя, команды, MAPPO,** процедурные карты, сценарии-упражнения.
6. **Сеть в браузере,** человечность, уровни сложности, плейтесты.
7. **Командир:** бойцы с приказами → командир на правилах → нейросетевой командир.
8. **Постоянно:** цикл «правка баланса → дообучение» и автотест «новый бот выигрывает у эталона не меньше X%».

## 9. Открытые вопросы

- Жанр и оружие: стрельба или ближний бой, как в текущем прототипе с рыцарем.
- Железо для обучения: CPU, есть ли видеокарта.
- Мультиплеер: авторитетный сервер на Node мог бы использовать то же ядро `sim/`.
- Видит ли человек контакты союзников-ботов (общая «рация» для всех)?
- Будут ли разрушаемые укрытия?
- Подавление: включать ли и насколько сильное.

## 10. Источники и примеры

- **OpenAI Five** (Dota 2): игра против себя, длинный горизонт, командная игра на огромных вычислениях.
- **AlphaStar** (StarCraft II): лига с «эксплойтерами», ограничение частоты действий.
- **DeepMind FTW** (Quake III, захват флага): популяция агентов, рекуррентная память.
- **GT Sophy** (Gran Turismo 7): нейросетевой соперник в коммерческой игре.
- **MotoGP 19, ANNA:** нейросетевые гонщики.
- **Supreme Commander 2:** гибрид — сеть решает «драться или отступать», остальное делают скрипты.
- **RocketSim** (Rocket League): сообщество написало отдельный быстрый движок без графики ради обучения ботов.
- **OpenAI Hide-and-Seek (2019):** агенты в прятках сами научились строить укрытия и блокировать двери.
- **Overcooked (2019):** боты, обученные только с копиями себя, плохо играют с людьми.
- **World of Tanks:** механика сведения. **Door Kickers, Darkwood:** сектор обзора.
